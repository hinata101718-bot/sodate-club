## 段階1：土台と、試作の手ざわりを本番へ

### できたこと
- Vite ＋ TypeScript ＋ Vitest の土台（`npm test`・`npm run build`・`npm run dev`）
- GitHub Actions で GitHub Pages に自動公開（`.github/workflows/deploy.yml`。main にプッシュすると、テスト → 組み立て → 公開）。Vite の `base` は `/sodate-club/`
- ホーム画面に追加して全画面で遊べる設定（`manifest.webmanifest`、`apple-touch-icon`、`apple-mobile-web-app-capable`）
- ゲームのしくみ（`src/core/`）と画面（`src/ui/`）を分けた。しくみ側にテストを書いた
- 試合のしくみ：試作の `simulateMatch` `resolveChance` `narrate` `pickHighlights` を移した（`src/core/match.ts` `narrate.ts` `phrases.ts`）
  - 乱数はシード付き（mulberry32）。乱数の状態はセーブに入るので、読み直しても同じように進む
  - 特殊能力は、企画書 8-8 の良い49・悪い8を全部データにした（`src/core/data/specials.ts`）。試合で効くものは全部、場面ごとの1対1にのせた（試作では一部だけだった）
- 試合の画面：1文ずつ・画面のどこを押しても進む・結果は最後・札を出さない・特殊能力の札とカットイン・ゴールのカットイン・自動スクロール・最後まで出す・実況（キックオフ・流れ・ファウル・前半終了・後半開始・交代・試合終了）。試合のあとのまとめ（結果・得点者・出場した選手）
- 週の報告（+2以上で光る）と、大きな覚醒の全画面（「覚醒！！」、台詞なし）
- 選手の一覧・選手の画面（8角形の能力図、2列×4行、ポジション適性、特殊能力を押すと説明、記録）
- 監督への方針（若手多め・ふつう・勝ち優先）と「この選手を使ってほしい」
- 「1週進む」「次に決めることまで進む」
- セーブ：自動セーブ1つ＋手動3枠、版の番号つき。localStorage が使えないときや、こわれたデータでも落ちない
- クラブの色で画面を染める。暗い画面でも読めるように、文字に使うクラブの色は自動で明るさを調整する

### 判断したこと
- 試合の数字：試作の数字のままだと1試合の平均得点が2.05点で、目安（2.0〜3.0）の下ぎりぎりだった。決定機の基本の回数（15分ごとに1.75回 → 2.0回）だけ上げて、約2.4点にした。強いほうの勝ち（力の差3〜6）は約64%
- 「強いほうの勝ちが6〜7割」は、引き分けもふくめた全試合のうち、強いほうが勝った割合で数えた（きびしいほうの数え方）
- 特殊能力の効き目は、試作の表にないものも企画書 8-8 の「効く場面」「効き目」から数字を決めた（平均で+5〜8、めったにない場面ほど強め）。マンマーク・クリーンディフェンス・コーチング・プレーの好み系は、能力ではなく「場面の起きやすさ」「関わる選手の選ばれやすさ」で効かせた
- 「フリーキックの名手」のために、セットプレーの中に「直接ねらうフリーキック」を入れた（場面の種類は11のまま）
- ホーム画面の下のメニューは、段階1では「ホーム・選手・順位」と右上の「設定」（セーブ・画面の明るさ・音）にした。段階4で企画書 14-1 の形にそろえる
- 画面の明るさは、端末に合わせる／明るい／暗い を選べるようにした
