# 指示書 夜1（5段階をまとめて作る）

このリポジトリ（hinata101718-bot/sodate-club）に、サカつく風のクラブ経営ゲームの本番を作ってください。
作業するあなたは、作業中にヒナタさん（監修役）へ質問できません。迷ったら、下の「読むもの」から判断して進め、判断したことを報告書に書いてください。

## 読むもの（この順に、最初に全部読む）

1. `docs/new/kikaku.md`（企画書）……作るものの正本。★はClaudeが決めたところ。★のないところはヒナタさんが決めたところなので、変えない
2. `docs/feedback.md`（試作への感想20件）……試合と週の報告の見せ方は、ここで決まったとおりに作る
3. `docs/new/hearing.md`（ヒアリング記録）……企画書でわからないときに、ヒナタさんの言葉を確かめる
4. `prototype/index.html`（試作 v7）……試合のしくみ（場面ごとの1対1）、文の作り方、見どころの出し方、カットイン、週の報告、覚醒、8角形の能力図、特殊能力の説明の、動く見本。数字の調整もここで済んでいる

企画書と試作が食い違うときは、試作で決まったこと（feedback.md）を優先する。それでも決められないときは、企画書の★のない部分（ヒナタさんの決定）に合うほうを選び、報告書に書く。

## いつも守ること

- **止まらない**：質問で止まらない。読むものから判断して進め、判断は報告書に書く
- **プッシュ先**：段階が1つ終わるたびに、`npm test` と `npm run build` を通してから、main にコミットしてプッシュする。作業用のブランチだけに入れない。どの段階のあとも、最初から遊べること
- **セーブ**：既存のセーブを壊さない。セーブの形を変えたら、版の番号を上げて、古い版から変換する処理を書き、そのテストを足す
- **iPhone**：Safariを第一に考える
  - 幅360〜430pxで崩れないこと
  - タップするところは44px以上、文字は12px以上
  - ホーム画面に追加して、全画面で遊べること（manifest と apple-touch-icon を用意する）
- **画像の色を読み取る計算（getImageData）は使わない**（ブラウザが色を乱すため）
- **数字のバランス**：試しに回す長さは、調整の途中は短く（1〜2シーズン）、長いもの（10シーズン）は最後に1回だけ。調整は2回まで。前の回の数字は `docs/reports/balance.md` に保存して、それと比べる
- **画面の撮影**：最後にまとめて1回（段階5で）
- **報告書**：`docs/reports/night1.md` に、段階ごとに書く（形は下の「報告書の書き方」）
- **ヒナタさんが「直さなくてよい」と言った数字**：今のところない。あれば、その数字は調整の目標にしない
- **名前**：クラブ・リーグ・選手・監督などの固有名詞は、すべてオリジナル。既存の作品の名前や、決まった仕組みの名前は使わない（「特殊能力」というしくみ全体の名前と、ポゼッションなどの現実の戦術名はヒナタさんが決めたので使ってよい）。国・県・市の名前は本物を使う
- **描写**：恋愛は描かない
- **言葉づかい**：画面の言葉は、やさしい日本語。専門用語には短い説明を添える

## 作り（技術の決めごと）

- Vite ＋ TypeScript。テストは Vitest
- `npm test` でテスト、`npm run build` で組み立て。`npm run dev` で手元で動く
- 外から読みこむのは Google Fonts だけ（M PLUS Rounded 1c と Noto Sans JP。試作と同じ）。ほかのライブラリは、必要なら npm で入れて組み立てに含める
- GitHub Pages に、GitHub Actions で自動公開する（`.github/workflows/deploy.yml`、main にプッシュしたら公開）。Vite の `base` は `/sodate-club/`
- 試合の計算・育成・お金などの「ゲームのしくみ」と、画面の表示は、ファイルを分ける。しくみの部分にテストを書く
- 乱数はシード付き（試作と同じ考え）。テストで結果を再現できるようにする
- セーブは localStorage（自動セーブ1つ＋手動3枠、企画書15）。どの読み書きも失敗したときに落ちないようにする
- 画面は、自分のクラブの色で染まる（企画書14、問46）。明るい画面と暗い画面の両方で読めること

## 段階1：土台と、試作の手ざわりを本番へ

作るもの
- 上の「作り」のとおりの土台、自動公開、ホーム画面に追加できる設定
- 試作の中身を、本番の形に移す
  - 試合のしくみ（企画書13-2、試作の `simulateMatch` `resolveChance` `narrate` `pickHighlights`）
  - 試合の画面（企画書13-1の「試作で決まった見せ方」すべて：1文ずつ、画面のどこを押しても進む、結果は最後、札を出さない、特殊能力の札とカットイン、ゴールのカットイン、自動スクロール、最後まで出す、実況）
  - 週の報告（+2以上で光る）と、大きな覚醒の全画面（「覚醒！！」、台詞なし）
  - 選手の一覧・選手の画面（8角形の能力図、2列×4行の数字、ポジション適性、特殊能力を押すと説明、記録）
  - 監督への方針（若手多め・ふつう・勝ち優先）と「この選手を使ってほしい」
  - 「1週進む」「次に決めることまで進む」
- セーブ（自動＋手動3枠、版の番号つき）

終わったら遊べること：試作と同じ遊び（3部の1シーズン以上）を、公開したページで、iPhoneのホーム画面から遊べる

テストに入れること：試合の得点が1試合平均2.0〜3.0点、力の差が3〜6の試合で強いほうの勝ちが6〜7割（企画書13-2・問54）。セーブして読み直すと同じ状態にもどる

## 段階2：世界とリーグ

作るもの（企画書3・5・6・7）
- はじめの画面：47都道府県から1つ選ぶ（代表の市つき）→クラブの名前・色・エンブレム（形と色の組み合わせ）を決める→3部から始まる
- 3段×12クラブ・全36クラブ（相手の35クラブは、自分の県以外の35県に1つずつ）
- 年22試合、上位2つが昇格・下位2つが降格、勝ち点と得失点差
- 全36クラブが出る勝ち抜きの大会（年1つ、引き分けはPK戦）
- 1年の流れ：1月オフ → 2月はじめ春の昇格会議 → 2月なかばキャンプ → 3月開幕〜11月 → 夏と冬の移籍期間 → 12月 表彰・契約更新（企画書6の表。順番は「昇格会議 → キャンプ → 開幕」で変えない）
- 節目の目標は成績の目標だけ（企画書7、問16）。ゲームに終わりはない
- 段ごとの強さの目安を守る（企画書8-2：3部の先発50〜60、2部65〜70、1部の平均72〜75、1部のMVPクラス82〜85）
- 順位表・大会の勝ち上がり表

終わったら遊べること：自分の県のクラブで、何シーズンも続けて昇格を目指せる

## 段階3：選手の中身

作るもの（企画書8・9-1）
- 能力8項目（1〜99、100はない）、GKの入れかえ、色（〜69灰・70〜79銅・80〜89銀・90〜99金）
- ポジション8つと適性（◎○△×、◎は平均1〜2・多くて4、使うと伸びる）
- 成長期は選手ごとにバラバラ（多くは16〜28歳）、ポテンシャル（上限88、シーズンの活躍で少し上下）、引退（下限なし）
- 特殊能力：良い49・悪い8（企画書8-8の表のとおり。名前も表のとおり）、1人0〜5つ、身につく・克服する、押すと説明
- 体の特徴（身長・利き足）、経歴と記録
- ユース：月1回の報告会議（成績・言葉と矢印の成長記録・ユースコーチのコメント）、春の昇格会議（ここで初めて数字が見える）

終わったら遊べること：地元のユースの子が、何年もかけて化けていくのを追える

## 報告書の書き方（docs/reports/night1.md）

段階ごとに、次を書く。

- できたこと／未完成のこと
- ヒナタさんに見てほしいところ（3つまで。どの画面のどこかを具体的に）
- 判断したこと（読むものだけでは決まらなかったところと、どう決めたか）
- かかった時間

最後に、公開したページのURLと、iPhoneでの試し方（ホーム画面への追加のしかた）を書く。
