# 遊んだ感想の記録

書き方：日付・どこで・ヒナタさんの言葉・原因（どのファイルの、どの決め方か）・直し方・状態

## 試作（prototype/index.html）

### 1. 2026-11-10　試合の見どころ（第1節、崩しからのゴール）
- ヒナタさんの言葉：「いきなりゴールが入るとワクワク感がない」
- 原因：prototype/index.html の `sceneHTML` が、場面のカードを出した瞬間に、見出しへ「ゴール！」の札と、能力のくらべ合い（勝ち・負け）を同時に出していた。点数の表示も、カードを出したと同時に変わっていた。結果が先に見えてしまう決め方だった
- 直し方：場面を「展開 → 勝負 → 結果」の3〜4行に分けて、少しずつ（約0.8秒ずつ）出す。「ゴール！」の札・点数・能力のくらべ合いは、最後の行が出てから出す
- 状態：直した（試作 v2）

### 2. 2026-11-10　試合の見どころ（第1節、守りのミスの場面）
- ヒナタさんの言葉：「実況がただ結果に飛ぶだけになっている」
- 画面の文：「和田 陽斗 のパスが弱い。和田 陽斗 はなんとか体を入れて取り返した。」
- 原因：prototype/index.html の `narrate` が、1つの場面を1文で書いていて、組み立て（溜め）がなく結果に飛んでいた。さらに「守りのミス」の場面で、ミスをした選手と取り返した選手に、同じ選手（`def`）を使っていた
- 直し方：どの場面も、展開・勝負・結果を別の行で書く。「守りのミス」で取り返すのは、ミスをした選手とは別の守りの選手にする
- 状態：直した（試作 v2）

### 3. 2026-11-10　試合の見どころ（第8節、GKが止めた場面）
- ヒナタさんの言葉：「この表記はいらないかも」（「守りの見せ場」の札）
- 原因：prototype/index.html の `sceneHTML` が、見どころに選んだ理由（守りの見せ場）を、札として画面に出していた
- 直し方：札は出さない。場面は、これまでどおり見どころには選ぶ
- 状態：直した（試作 v2）
