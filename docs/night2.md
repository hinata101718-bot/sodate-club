## いつも守ること（夜1と同じ）

- **止まらない**：質問で止まらず、読むものから判断して進め、判断は報告書に書く
- **プッシュ先**：段階ごとに `npm test` と `npm run build` を通してから、main にコミットしてプッシュする。どの段階のあとも、最初から遊べること
- **セーブ**：既存のセーブを壊さない。形を変えたら版を上げ（いまは版4のはず。夜1のあとに上がっていれば、その次）、古い版から変換する処理とテストを足す。**ヒナタさんはもう遊んでいるので、いまのセーブがそのまま続きから遊べること**
- **iPhone**：Safariを第一に。幅360〜430pxで崩れない。タップは44px以上、文字は12px以上。ホーム画面から開いても見出しが隠れない
- **getImageData は使わない**
- **数字のバランス**：試しは短く（1〜2シーズン）、長いもの（10シーズン）は最後に1回。調整は2回まで。前の回の数字は `docs/reports/balance.md` と比べる
- **画面の撮影**：最後にまとめて1回（`docs/reports/shots/` に足す）
- **名前はオリジナル**。値段の交渉のやりとりは入れない（問52）。選手の気持ちのしくみは入れない（問52）
- **報告書**：`docs/reports/night2.md`（できたこと／未完成、見てほしいところ3つまで、判断したこと、かかった時間）

## 段階1：移籍市場のしくみ（画面はまだ最低限でよい）

- 移籍の期間（7〜8月・12月）に、他の35クラブのどの選手にも獲得の申し込みができる
- 移籍金の「相場」を決める式：能力・年齢・契約の残り年数・いる段で決まる。高めにして、育成が芯のまま残るようにする
- 相手のクラブが「売る・売らない」を決める：先発の上位は売りにくく、控えや契約が残り1年の選手は売りやすい
- 選手本人が「行く・行かない」を決める：上の段の選手ほど下の段のクラブには来にくい。給料の上乗せ（たとえば0%・+20%・+50%の3つから選ぶ）で来やすくなる。決めるのは段と給料だけ
- 契約が切れて、どこにもいない選手（フリー）を作る。12月の契約更新で他クラブが更新しなかった選手が入る。移籍金なし、給料は高め
- スカウトへの希望に「即戦力（すぐ先発で使える選手）」を足す。年齢を問わず、移籍金つきの候補として届く
- 他のクラブ同士の移籍：移籍の期間に、強いクラブが補強する。段ごとの強さの目安（企画書8-2）がくずれないこと
- 選手の「市場の値段」を計算する（自分の選手にも出す）
- テスト：相場が能力と年齢で上下する、主力は売られにくい、上の段の選手は下の段に来にくい、セーブの変換

## 段階2：移籍市場の画面

- 「移籍・候補」の画面に、移籍市場を足す
  - さがし方：ポジション・総合力の範囲・年齢の範囲・段・「市場の値段」の上限で絞りこめる
  - 一覧：名前・ポジション・年齢・総合力・いるクラブ・市場の値段
  - 選手を押すと選手の画面（他クラブの選手も、8角形の図・特殊能力の説明が見られる。ただし隠れたポテンシャルは見えない）。そこから「獲得を申し込む」（給料の上乗せを選ぶ）
  - 結果は、次の週のお知らせで届く（売ってくれた／断られた、来てくれた／断られた）
- フリーの選手の一覧
- 自分の選手の画面に「市場の値段」を出す
- お知らせに「移籍のニュース」（他クラブ同士の大きな移籍）を出す
- 「次に決めることまで進む」は、申し込みの結果が届いたら止まる

## 段階3：仕上げ

- 数字の確かめ：10シーズンを1回。見る数字は、移籍金の大きさとお金の増え方、段ごとの先発の総合力（目安からずれていないか）、自分のクラブが買った選手と育てた選手の割合
- 画面の撮影（移籍市場・申し込み・結果のお知らせ）
- 報告書をまとめる。最後に、公開したページで移籍市場を試すやり方を書く
